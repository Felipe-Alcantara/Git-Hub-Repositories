## 🪵 Logs & Depuração (novo)

Adicionei logs detalhados em todo o fluxo de download / salvamento / armazenamento de projetos para facilitar debugging e observabilidade.

Onde os logs foram adicionados:
- `src/utils/storage.js` — operações de leitura/gravação/import/export, migrações, ordem de projetos, grupos
- `src/utils/github.js` — chamadas à API do GitHub (repo, linguagens, README, arquivos) com informações de rate-limit
- `src/utils/gist.js` — sincronização (criar/atualizar), carregamento, exclusão e gestão do Gist ID no localStorage
- `src/utils/aiStorage.js` — save/load/delete das conversas de IA (IndexedDB + fallback)
- `src/hooks/useProjects.js` — logs no hook que adiciona/atualiza/deleta/reordena projetos
- Componentes relevantes (ex.: `GistSyncModal.jsx`, `ImportExportButtons.jsx`, `NewProjectModal.jsx`, `ImportProfileModal.jsx`, `ProjectPage.jsx`, `Home.jsx`) também receberam logs de ação/erro/estado

Como visualizar os logs:
- Abra as DevTools do navegador (F12) → aba Console.
- No filtro de nível de mensagens escolha "Verbose" / "All" para ver `console.debug` e `console.info`.

Mensagens úteis que você verá:
- [storage] ... — operações locais (get/save/add/update/delete/import/export)
- [GitHub] ... — requisições e resultados do GitHub (inclui X-RateLimit-Remaining quando disponível)
- [Gist] ... — upload/backup/restore do Gist
- [aiStorage] ... — operações de persistência do histórico de IA
- [useProjects] / [Home] / [ProjectPage] / [GistSyncModal] ... — ações disparadas via UI

Notas de produção:
- Estes logs são voltados para desenvolvimento; em ambientes de produção você pode ajustar o nível de logs nas DevTools (ou remover insights sensíveis) antes de publicar.

## 💡 Como Funciona

### 📥 Importação de Repositórios GitHub

#### Importação Individual
1. Clique em "Novo Projeto"
2. Cole a URL de qualquer repositório GitHub
3. Clique em "Buscar do GitHub"
4. Dados são preenchidos automaticamente:
   - Nome e descrição
   - Linguagens com estatísticas
   - README original em Markdown
   - Links do repositório
   - Autor/owner
5. Ajuste os detalhes e salve

#### Importação em Lote
1. Clique em "Importar Perfil"
2. Cole o nome de usuário ou URL do perfil GitHub
3. Selecione os repositórios desejados
4. Todos os repositórios são importados com:
   - Informações completas
   - Estatísticas de linguagens
   - README automático
   - Metadados do GitHub

#### Configuração de Token (Recomendado)
1. Clique no ícone de configurações (⚙️)
2. Cole seu Personal Access Token do GitHub
3. Benefícios:
   - Evita limite de 60 requisições/hora
   - Acesso a repositórios privados
   - Importação mais rápida

**Como criar token:**
1. Acesse [GitHub Settings > Developer Settings > Personal Access Tokens](https://github.com/settings/tokens)
2. Clique em "Generate new token (classic)"
3. Marque: `repo`, `read:user`, `gist`
4. Gere e copie o token

### ☁️ Sincronização via Gist

#### Fazer Backup
1. Configure seu token do GitHub
2. Clique em "Sincronizar"
3. Escolha "Fazer Backup"
4. Seus projetos são salvos em um Gist secreto
5. **Guarde o ID do Gist** para sincronizar em outros dispositivos

#### Restaurar de Backup
1. Clique em "Sincronizar"
2. Escolha "Restaurar"
3. Cole o ID do Gist
4. Visualize os dados antes de importar
5. Confirme para substituir seus projetos locais

#### Deletar Backup
1. No card "Gist Conectado"
2. Clique em "Deletar Backup"
3. Confirme a exclusão permanente
4. O backup é removido do GitHub

### 💾 Import/Export Local

#### Exportar Projetos
1. Clique em "Exportar Projetos"
2. Um arquivo JSON será baixado com todos os seus projetos
3. Use para backup local ou compartilhamento

#### Importar Projetos
1. Clique em "Importar Projetos"
2. Selecione um arquivo JSON exportado
3. Os projetos serão adicionados aos seus existentes

## 🔒 Privacidade e Segurança

### Dados Locais
Todos os dados dos projetos são armazenados **localmente no localStorage do seu navegador**. Nada é enviado para servidores externos automaticamente. Seus projetos são 100% privados e só você tem acesso.

### GitHub API
Quando você importa repositórios do GitHub:
- Apenas dados públicos são acessados (ou seus repos privados se configurar token)
- Repositórios privados exigem token com escopo `repo` e são listados no seu próprio perfil autenticado
- Requisições são feitas diretamente para a API do GitHub
- Nenhum intermediário ou servidor próprio
- Token é armazenado apenas no seu navegador

### Sincronização via Gist (Opcional)
Se você escolher usar a sincronização:
- Dados são salvos em um **Gist secreto** na sua conta GitHub
- Apenas você tem acesso (Gist não-listado)
- Você controla quando fazer backup/restaurar/deletar
- Token com permissão `gist` necessário
- Sem acesso de terceiros

### Google Gemini API
Quando você usa as funcionalidades de IA:
- Dados são enviados para a API do Google Gemini
- Apenas contexto do projeto (README, estrutura) é compartilhado
- Respostas são processadas localmente no navegador
- Token é armazenado apenas no seu navegador
- Sem armazenamento permanente de dados na API

### Recomendações
- ✅ Use token do GitHub para melhor experiência
- ✅ Configure API Key do Gemini para funcionalidades de IA
- ✅ Faça backups regulares (export JSON ou Gist)
- ✅ Não compartilhe seus tokens com ninguém
- ✅ Revogue tokens não utilizados

## 🤝 Contribuindo

Contribuições são muito bem-vindas! Este projeto está em desenvolvimento ativo e toda ajuda é apreciada.

### Como Contribuir

1. **Fork** o projeto
2. Crie uma **branch** para sua feature (`git checkout -b feature/MinhaFeature`)
3. **Commit** suas mudanças (`git commit -m 'Adiciona MinhaFeature'`)
4. **Push** para a branch (`git push origin feature/MinhaFeature`)
5. Abra um **Pull Request**

### Áreas para Contribuir

- 🐛 **Reportar bugs** - Encontrou um problema? Abra uma issue!
- ✨ **Sugerir features** - Tem uma ideia legal? Compartilhe!
- 📝 **Melhorar documentação** - Documentação nunca é demais
- 🎨 **Melhorias de UI/UX** - Design e experiência do usuário
- 🧪 **Testes** - Adicionar testes automatizados
- 🌐 **Traduções** - Suporte a outros idiomas
- ♿ **Acessibilidade** - Melhorar a11y

### Guidelines

- Mantenha o código limpo e bem documentado
- Siga os padrões de código do projeto
- Teste suas mudanças antes de submeter
- Descreva claramente o que sua PR faz

### Reportar Bugs

Ao reportar bugs, inclua:
- Descrição clara do problema
- Passos para reproduzir
- Comportamento esperado vs atual
- Screenshots se aplicável
- Navegador e versão

